# プロトタイプ評価:武装ハント(2026-11-17)

試作:`Assets/Prototype/HuntRelease`(ブランチ `prototype/stage-weapons`、コミット `4265e98`)

## 1. 何を確かめる試作だったか

企画の核「**重厚な剣戟から、軽快に無双するまで自機を成長させる。その落差と成長の実感が面白さ**」を、次の仕組みで成り立たせられるかを確かめた。

- 素の自機は弱く重い(右手の剣だけ)。
- 武装は敵から手に入れ、使い切ると外れる(強さを積み上げ続けない)。
- 武装がそろうほど、戦い方そのものが変わる(射撃・砲撃・高速移動)。

## 2. 試作の中身(評価時点)

| 項目 | 内容 |
|---|---|
| 進行 | ステージ攻略型。2ステージ・計10区画(高低差・閉所あり)。区画の敵を全滅させると扉が開く。各ステージの最後にボス |
| 武装の入手 | 倒した敵がランダムで落とす(部位破壊した部位は追加で落ちることがある)。宝箱からも出る |
| 装備 | 入手した武装は在庫に入り、装備メニュー(時間停止)で付ける。右手・左手・右肩・左肩・背中の5か所 |
| 武装の種類 | 腕刃(剣の威力とリーチが伸びる)・ガトリング・キャノン・バックパック(ブースト中だけ働く:速さ・上昇・回避距離) |
| 使い切り | どの武装も使用回数があり、尽きると外れる。素の剣だけは外れない |
| 品質 | 4段階(粗悪・標準・上物・逸品)。威力と使用回数が変わる。武装の色で見分ける |
| 機動 | 走り60.12 km/h、ブースト90 km/h、上昇(高さの上限なし・エネルギー制)、回避 |
| 狙い | ロックオン(150m)、手動照準(△長押し)。射撃は地形でさえぎられる |
| 被弾 | 敵の射撃・砲撃は自機の速さに応じて正規分布でぶれる(速く動くほど外れやすい) |
| 回復 | 回復アイテム(最初3個・最大10個) |

### 試作の途中で決まったこと

- **装備のタイミング**:溜めて一気に解放する方式より、拾った武装を在庫から選んで付ける方式を選んだ。
- **入手の仕方**:部位を斬り落として剥ぐ方式より、倒すとランダムで落とす方式を選んだ。部位破壊は追加で落ちる確率を上げる位置づけ。
- **進行**:平地で「狩り→群れ→バケモノ」をこなす1サイクルより、ステージ攻略型を選んだ。ステージ攻略型では獲物と群れの区別に意味がなくなったので、1種類の通常の敵にまとめた。
- **被弾**:無敵時間の代わりに、速さに応じた当たりにくさにした。

## 3. 評価結果

| 観点 | 評価 |
|---|---|
| 1. 重厚→無双の落差 | 差は出ている。ただし**剣だけの戦いがあまり面白くない** |
| 2. 武装の入手・使い切り・付け替え | **メニューを開く頻度が高い** |
| 3. 品質差による選択 | **ボスまで温存し、ボスで強いものを使うと単調** |
| 4. 機動の気持ちよさ | まあいい |
| 5. ステージ(高低差・閉所) | **ステージ攻略感は面白い**。壁から半身を出して砲撃する、などが生まれた |
| 6. 難易度 | **近接で複数の敵に囲まれると理不尽に感じる** |

## 4. コンセプトの評価

- **落差そのものは作れる**:素の状態と武装がそろった状態で、戦い方がはっきり変わることは確かめられた。
- **ただし出発点が弱い**:「重厚な剣戟」が手応えではなく退屈さとして出ている。今の剣は「近づいて3段振る」だけで、敵の攻撃を読んで返す手段がない。出発点が面白くないと、落差は「つまらない状態から抜け出す」だけになり、核の面白さにならない。**剣戟の土台を作り直すことが最優先**。
- **「使い切りの武装」は温存を生む**:武装を在庫に溜められるため、道中で使わずボスに持ち込むのが最善手になっていた。武装の入手と消費の巡りを、道中で使いたくなる形に組み直す必要がある。企画の原則「ボス撃破でほぼ全リセット」とも結びつけて考えたい。
- **予想外の収穫はステージ攻略**:高低差・閉所・遮蔽物が、射撃武装の使い方(遮蔽から半身を出して撃つ、高台の砲台を崩す)を生んだ。武装がそろったあとの遊びの幅として、ここが一番伸びしろがある。

## 5. 伸ばすべきところ

1. **ステージ攻略感**:遮蔽物と高低差を生かした戦い。遮蔽を意識した敵の配置、高台の砲台役、閉所と開けた場所の緩急。
2. **武装で戦い方が変わること**:手に剣か銃か、肩の砲撃、バックパックでの機動など、付けたもので遊び方が変わる手触り。
3. **機動**:今の走り・ブースト・飛行・回避は「まあいい」。土台として残す。

## 6. 次に取り組むこと(案)

| 優先 | 課題 | 案 | 規模 |
|---|---|---|---|
| 1 | 剣だけの戦いが面白くない | 剣に「読んで返す」動きを足す(例:敵の振りに合わせて弾く→敵がよろける→大技)。電脳斬禅の剣戟の要素を土台にする | 大 |
| 2 | 複数に囲まれると理不尽 | 同時に近接攻撃できる敵を1〜2体に絞り、残りは間合いの外で待つか射撃に回る(攻撃の順番待ち) | 小 |
| 3 | メニューの頻度が高い | 空いている場所へは拾った時に自動で付ける。使い切ったら同じ場所へ在庫の最良品を自動で付ける | 小 |
| 4 | 温存して単調 | 在庫の上限を小さくする。加えて「ステージをまたぐと在庫が消える」か「ボスが戦いの中で部位を落とし、ボス戦の中で落差を作る」 | 中 |

## 7. 決めること

- 剣戟の土台:電脳斬禅の剣戟から、どの要素を持ってくるか。
- 武装の持ち越し:ステージ(ボス)をまたいで何を残し、何を失うか。
- ボスの作り:今は「大きくて全部位を持つ敵」で、固有の攻撃がない。ボス戦を一つのサイクル(重厚→無双)にするかどうか。

## 8. 評価時点の既知の制約

- ボタン操作の確認の多くは内部処理を直接呼んで行っており、実機パッドでの操作感の確認は少ない。
- 敵の強さ・数はほぼ未調整。
- キーボードでは歩けない(常に走り)。敵は倒すと復活しない。
- 溜めて解放するモード(SHARE+□ / F2)と、平地の旧モード(`useStage`)が残っている(評価の対象外)。
- 地形・宝箱・落ちた武装は仮の見た目。天井は影を落とさない設定。
